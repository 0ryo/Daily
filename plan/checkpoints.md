# チェックポイント（AIなし課題と人間レビュー）

> この計画が想定する前提：毎月1回、制限時間つきで AI を使わずに解く課題（CP）と、自分以外の人からフィードバックを受ける機会（HR）を設ける。日付と範囲は目安。2026-10-24 から、実施する日は短期目標（plan/short-term/）を立てるときに決め、範囲はその月の中期目標（plan/goals.md）と、それまでに学んだ内容に合わせて調整する。予定が合わない場合は同じ月の中で動かす。

## AIなし課題（CP）

### 目的
CP は、AI や過去のコードがない状態で、一人でどこまで書けるかを測る日。測った結果（一人で書けなかったこと）を、次に何を練習するかを決めるのに使う。普段の課題は「できるようになる」ための練習なので、制限を付けない。

### 共通のルール（それぞれの理由）
- **使ってよいもの**：Apple の公式ドキュメント、The Swift Programming Language、Xcode の候補の一覧（入力中に出る通常のコード補完）。理由：API 名や引数の暗記には意味が小さく、実務でもドキュメントを引くため。
- **過去の自分のコードを見ない**。理由：何も見ずに思い出して書くと、見ながら書くより記憶に残りやすい。CP の学習効果の中心はここにある。
- **AI を使わない**（Claude Code、ChatGPT、Xcode のコーディングアシスタントと予測補完。始める前に Xcode の設定で切る）。理由：予測補完は処理の中身をまとめて書くので、自分で考えて書いたかどうかを区別できず、測れなくなる。実務で使うのは当然なので、切るのは CP の日だけにする。Web 検索で見つけたコード例も同じ理由で使わない。
- **制限時間**：始まりと終わりの時刻を記録する。理由：CP が長引いて翌日の学習に響くのを防ぐため。時間内に終わったかどうかで点数を付けない。かかった時間は、慣れの目安として記録する。
- **結果の記録**：締め切りの時点のコミットで「一人で書けたこと・書けなかったこと」と「かかった時間」を記録する。点数は付けない。理由：次の練習を決めるのに必要なのは、数字ではなく書けなかったことの中身だから。
- **締め切り後の修正**：普段の課題と同じく、再提出のたびに採点して100点まで進める。理由：実務と同じく、指摘を受けて直す力も育てるため。締め切りの時点の記録は書き換えない。
- **類題**：一人で書けなかったことが、その CP の「範囲」の中心にあれば、2週間以内に同じ範囲の類題（`-cpNr`）を AI なしで解く。名前の付け方やアクセス制御のような周辺の指摘だけなら、類題は出さず、普段の課題で扱う。
- 置き場所は、学習者が用意した日付の名前のフォルダ（例：`1117/`）でもよい。

## 人間レビュー（HR）

### 共通のルール
- 自分以外の人間から、コード・設計・成果物について1件以上の具体的なフィードバックをもらうことを達成条件とする。
- もらったフィードバックは GitHub の Issue にし、対応したかどうかを記録する。
- 勉強会は connpass などで、iOS・Swift のオンラインまたは近場のイベントを探す。

| HR | 週 | 時期 | 形式 | 達成条件 |
|---|---|---|---|---|
| HR1 | 2〜3 | 2026年10月下旬 | iOS・Swift の勉強会（もくもく会でも可）に参加する | 自分の課題のコード（例：単元4の統合課題）について質問し、1件以上のコメントをもらう |
| HR2 | 7 | 2026年12月3日 | OSS への PR（1件目） | ドキュメントの誤り・サンプルの不具合など小さな修正の PR を提出し、メンテナーの反応を記録する |
| HR3 | 9 | 2026年12月17日 | App1 の設計レビュー | 要件定義・画面遷移図・データモデルを勉強会・知人・入社先の窓口などに見せ、指摘を Issue にする |
| HR4 | 14 | 2027年1月18日 | App1 のユーザーテスト | App Store 版を3人以上に使ってもらい、感想を Issue にする |
| HR5 | 19 | 2027年2月24日 | OSS への PR（2件目） | コードの変更（不具合の修正、テストの追加など）を含む PR を提出する |
| HR6 | 23 | 2027年3月25日 | LT、または入社先の担当者への成果物の共有 | 「UIKit アプリに SwiftUI を段階導入した話」などを5分で発表し、質問や感想を1件以上もらう |

## 記録のしかた
各 CP・HR のあと、週の振り返りに次の3点を書く。
1. 結果（点数、または得られたフィードバック）
2. 時間内にできなかったこと、または指摘されたこと
3. 次の2週間で直すこと
