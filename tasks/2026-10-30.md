# 10/30（金）ToDo の一覧を、ファイルがなくても壊れていても空の一覧で始める
- 作業場所：`1030/`（Xcode の Command Line Tool プロジェクト。Playground が動かないため、10/29 と同じ形で作る）
- 想定時間：2時間

## 要件
### 構造体
**1. TodoItem**
- プロパティ：`title`（String、やることの名前）、`isDone`（Bool、終わったかどうか）
- 関数：なし
- 特記事項：エンコードとデコードができる。CodingKeys は不要。

**2. TodoStorage**（ToDo の一覧をファイルに保存し、読み込み、削除する構造体）
- プロパティ：`fileURL`（URL、保存先のファイル。Documents ディレクトリの中の `todos.json`）
- 関数：
  - **2-1. `save(_ items: [TodoItem]) throws`**
    - 処理：ToDo の配列を受け取り、JSON にエンコードして、`fileURL` のファイルに書き込む。
    - 書き込み時は `.atomic` を指定する。
    - エンコードや書き込みに失敗したら、エラーを呼び出し元に投げる。
  - **2-2. `load() throws -> [TodoItem]`**
    - 処理：`fileURL` のファイルを読み込み、ToDo の配列にデコードして返す。
    - ファイルがないときは、エラーを投げずに空の配列を返す。
    - ファイルはあるがデコードに失敗したとき（壊れた JSON など）は、エラーを呼び出し元に投げる。
    - 「ファイルがない」「デコードに失敗した」以外の読み込みの失敗も、エラーを呼び出し元に投げる。
  - **2-3. `writeText(_ text: String) throws`**
    - 処理：テスト用に、受け取った文字列を UTF-8 のまま `fileURL` のファイルに書き込む。JSON への変換はしない。
    - 書き込みに失敗したら、エラーを呼び出し元に投げる。
  - **2-4. `deleteFile() throws`**
    - 処理：`fileURL` のファイルがあれば削除する。
    - ファイルがないときは、何もせずに終わる（エラーにしない）。
    - 削除に失敗したら、エラーを呼び出し元に投げる。

### 関数
**3. `loadItemsAtLaunch(from storage: TodoStorage) -> [TodoItem]`**
- 目的：プログラムの起動時に、最初に使う ToDo の一覧を用意する。保存データが読めないときも、プログラムを止めずに空の一覧で始める。
- 置き場所：TodoStorage の中ではなく、TodoStorage の外に普通の関数として書く。
- 引数：`storage`（ToDo の一覧を読み込むための TodoStorage）
- 戻り値：起動時に使う ToDo の配列
- 2-2 との違い：2-2 `load()` は、JSON が壊れているときにエラーを投げる。3 `loadItemsAtLaunch` は、`load()` が投げたエラーを受け止めて、空の配列を返す。
- 処理：
  - **3-1.** 引数 `storage` の `load()`（2-2）を呼ぶ。
  - **3-2.** `load()` が成功したら、`load()` が返した ToDo の配列を、`loadItemsAtLaunch` の戻り値として返す。
  - **3-3.** `load()` がデコードの失敗のエラーを投げたら、「保存データが壊れているため、空の一覧で始めます」と print して、空の配列を返す。
  - **3-4.** `load()` がデコードの失敗以外のエラーを投げたら、「読み込みに失敗したため、空の一覧で始めます」という文と、投げられたエラーの内容を print して、空の配列を返す。
  - **3-5.** `loadItemsAtLaunch` には `throws` を付けない。`load()` が投げたエラーはすべて `loadItemsAtLaunch` の中で受け止め、呼び出し元にはエラーを投げない。

### 守ること
- `!`、`try!`、`as!`、`try?` を使わない。
- TodoStorage の中では print しない。print は 3 とテストのコードで行う。
- テストごとに、何が成功したか、または何に失敗したかとエラーの内容を表示する。読み込んだときは件数も表示する。
