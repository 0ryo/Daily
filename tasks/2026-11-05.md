## パート1：保存に失敗したときに、アラートで伝えて入力を残す（約1.5時間）
### 構造体
**1. Plant**（育てている植物1件）
- プロパティ：`name`（String、植物の名前）、`wateringInterval`（Int、水やりの間隔の日数）
- 関数：なし
- 特記事項：エンコードとデコードができる。CodingKeys は不要。

**2. PlantList**（植物の一覧を持ち、追加する前に入力を確かめる構造体）
- プロパティ：`plants`（[Plant]、植物の一覧。外から読めるが、外から直接書き換えられない）
- 関数：
  - **2-1. `init(plants: [Plant])`**
    - 目的：最初に持つ植物の一覧を決めて、PlantList を作る。
    - 引数：`plants`（[Plant]、最初に持つ植物の一覧）
    - 戻り値：なし
    - 処理：
      - **2-1-1.** 引数 `plants` を、プロパティ `plants` に入れる。
  - **2-2. `makePlant(name: String, wateringInterval: Int) -> Plant?`**
    - 目的：入力が条件に合うときだけ、Plant を作って返す。
    - 引数：`name`（String、入力された植物の名前）、`wateringInterval`（Int、水やりの間隔の日数）
    - 戻り値：条件に合うときは作った Plant、条件に合わないときは `nil`
    - 処理：
      - **2-2-1.** `makePlant` が、`name` の前後の空白・改行を除去する。
      - **2-2-2.** 除去した後の名前が空のとき、または `wateringInterval` が 1〜30 の範囲にないとき、`makePlant` は `nil` を返す。
      - **2-2-3.** 条件に合うとき、`makePlant` は、除去した後の名前と `wateringInterval` で Plant を作って返す。`makePlant` は `plants` を変えない。
  - **2-3. `append(_ plant: Plant)`**
    - 目的：保存に成功した Plant を、一覧の末尾に加える。
    - 引数：`plant`（Plant、加える植物）
    - 戻り値：なし
    - 処理：
      - **2-3-1.** `append` が、引数 `plant` を `plants` の末尾に加える。
    - `makePlant(name:wateringInterval:)` との違い：`makePlant` は Plant を作るだけで `plants` を変えず、`append` は `plants` を変える。

**3. PlantStorage**（植物の一覧をファイルに保存し、読み込む構造体）
- プロパティ：
  - `fileURL`（URL、保存先のファイル）
  - `static let normalFileURL`（URL、Documents ディレクトリの中の `plants.json`）
  - `static let failingFileURL`（URL、Documents ディレクトリの中の `no-such-folder` フォルダの中の `plants.json`。`no-such-folder` フォルダは作らない。フォルダがないので、`failingFileURL` への書き込みは必ず失敗する）
- 関数：
  - **3-1. `init(fileURL: URL)`**
    - 目的：保存先のファイルを決めて、PlantStorage を作る。
    - 引数：`fileURL`（URL、保存先のファイル）
    - 戻り値：なし
    - 処理：
      - **3-1-1.** 引数 `fileURL` を、プロパティ `fileURL` に入れる。
  - **3-2. `save(_ plants: [Plant]) throws`**
    - 目的：植物の一覧をファイルに保存する。
    - 引数：`plants`（[Plant]、保存する植物の一覧）
    - 戻り値：なし
    - 処理：
      - **3-2-1.** `save` が、`plants` を JSON にエンコードする。
      - **3-2-2.** `save` が、エンコードした結果を `fileURL` のファイルに書き込む。書き込み時に `.atomic` を指定する。
      - **3-2-3.** エンコードや書き込みに失敗したら、`save` はエラーを呼び出し元に投げる。

### 画面
**4. PlantViewController**（画面は1つ）
- **4-1. 部品**：植物の名前の入力欄、水やりの間隔の入力欄（数字キーボード）、追加ボタン、「保存を失敗させる」と書いたラベルと UISwitch、結果ラベル、UITableView を置く。
- **4-2. 起動したとき**
  - **4-2-1.** PlantViewController が、空の配列で PlantList を作る。
  - **4-2-2.** PlantViewController が、`PlantStorage.normalFileURL` で PlantStorage を作る。
  - **4-2-3.** PlantViewController が、UISwitch をオフにし、結果ラベルに「植物を入力してください」と表示する。
- **4-3. UISwitch を切り替えたとき**
  - **4-3-1.** UISwitch がオンになったら、PlantViewController が `PlantStorage.failingFileURL` で PlantStorage を作り直す。
  - **4-3-2.** UISwitch がオフになったら、PlantViewController が `PlantStorage.normalFileURL` で PlantStorage を作り直す。
- **4-4. 追加ボタンを押したとき**
  - **4-4-1.** PlantViewController が、水やりの間隔の入力欄の文字列の前後の空白・改行を除去してから、Int に変換する。
  - **4-4-2.** どちらかの入力欄の文字列が取り出せないとき、Int への変換に失敗したとき、または PlantList の `makePlant`（2-2）が `nil` を返したとき、PlantViewController は結果ラベルを「名前と水やりの間隔を確認してください」にする。入力欄の内容と一覧は変えない。
  - **4-4-3.** `makePlant` が Plant を返したとき、PlantViewController は、PlantList の `plants` の末尾に作った Plant を加えた配列を用意し、PlantStorage の `save(_:)`（3-2）に渡す。この時点では、PlantList の `append(_:)` を呼ばない。
  - **4-4-4.** `save(_:)` が成功したら、PlantViewController は PlantList の `append(_:)`（2-3）で作った Plant を加え、一覧の表示を更新する。両方の入力欄を空にしてキーボードを閉じ、結果ラベルを「追加しました」にする。
  - **4-4-5.** `save(_:)` がエラーを投げたら、PlantViewController はエラーの内容を print し、結果ラベルを「保存に失敗しました」にする。PlantList の `append(_:)` は呼ばず、入力欄の内容と一覧は変えない。続けて、4-5 のアラートを表示する。
- **4-5. 保存に失敗したときのアラート**
  - **4-5-1.** PlantViewController が、タイトル「保存できませんでした」、メッセージ「入力した内容はそのまま残っています。もう一度お試しください。」の UIAlertController を、スタイル `.alert` で作る。
  - **4-5-2.** PlantViewController が、UIAlertController に「OK」のボタン（スタイル `.default`）を1つ加える。「OK」を押したときの処理は不要。
  - **4-5-3.** PlantViewController が、`present(_:animated:completion:)` で UIAlertController を表示する。
- **4-6. 一覧の行**：1行に1件の植物を「モンステラ：7日ごと」の形で表示する。並び順は PlantList の `plants` の順にする。

## パート2：起動したときに一覧を読み込み、失敗をアラートで伝える（約30分）
### 構造体
**3. PlantStorage**（パート1の続き）
- 関数：
  - **3-3. `load() throws -> [Plant]`**
    - 目的：保存されている植物の一覧を、ファイルから読み込む。
    - 引数：なし
    - 戻り値：読み込んだ植物の一覧
    - 処理：
      - **3-3-1.** `fileURL` のファイルがないとき、`load` はエラーを投げずに空の配列を返す。
      - **3-3-2.** ファイルがあるとき、`load` はファイルを読み込み、植物の配列にデコードして返す。
      - **3-3-3.** 読み込みやデコードに失敗したら、`load` は空の配列を返さずに、エラーを呼び出し元に投げる。

### 画面
**4. PlantViewController**（パート1の続き）
- **4-7. 起動したとき**（パート1の 4-2-1 を、次の処理に置き換える。`viewDidLoad()` の中で、4-2-2 → 4-7-1〜4-7-3 → 4-2-3 の順に行う）
  - **4-7-1.** PlantViewController が、4-2-2 で作った PlantStorage の `fileURL` を print する（テスト9で `plants.json` の場所を確かめるため。課題が終わっても残してよい）。
  - **4-7-2.** PlantViewController が、4-2-2 で作った PlantStorage の `load()`（3-3）を呼ぶ。成功したら、`load()` が返した配列で PlantList を作り、一覧に表示する。
  - **4-7-3.** `load()` がエラーを投げたら、PlantViewController は空の配列で PlantList を作り、エラーの内容を print する。PlantViewController は、読み込みに失敗したことを Bool のプロパティ `didFailToLoad`（初めの値は `false`）に `true` を入れて記録する。
- **4-8. 画面が表示されたとき**
  - **4-8-1.** PlantViewController が `viewDidAppear(_:)` を override し、最初に super の `viewDidAppear(_:)` を呼ぶ。
  - **4-8-2.** `didFailToLoad` が `true` のとき、PlantViewController は、タイトル「読み込めませんでした」、メッセージ「保存データを読み込めなかったため、空の一覧で始めます。」、「OK」のボタン1つの UIAlertController を表示する。アラートのスタイルとボタンのスタイルは、4-5-1・4-5-2 と同じにする。表示したあと、`didFailToLoad` を `false` に戻す。
