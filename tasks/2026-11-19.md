# 11/19（木）戻っても解放されない数取りの画面を見つけて直す

> 人数を数える画面を、わざと解放されない形で作り、Memory Graph Debugger と `deinit` で確かめてから直します。

- 作業場所：`1119/`（iOS App・XIB + Auto Layout）
- 想定時間：パート1 1.5時間／パート2 30分
- パート1だけで提出してよいです。
- Memory Graph Debugger は、メモリに残っているインスタンスと、インスタンス同士の参照を図で見る Xcode の機能です。アプリの実行中に、Xcode の下のデバッグバーにある Debug Memory Graph ボタンを押すと開きます。

## 守ること
- `!` `try!` `as!` `try?` を使わない（`@IBOutlet` の `!` は除く）
- 画面は XIB で作る。Main.storyboard には部品を置かない
- SceneDelegate で、`MenuViewController()` を最初の画面にした UINavigationController を、window の `rootViewController` にする
- `TallyCounter` は人数を数えて知らせるだけにする。ラベルの文字列（「3人」）を作るのは TallyViewController にする
- ブランチ `1119` で PR を作る（マージは不要）

## パート1：解放されない画面を作って確かめる（1.5時間）

### 画面 `MenuViewController`
最初の画面です。数取りの画面へ進むボタンだけを置きます。

- 部品：「数取りへ」ボタン

1. **「数取りへ」を押したとき**：`TallyViewController()` で作って push する

### クラス `TallyCounter`
人数を数え、人数が変わったことをクロージャで知らせるクラスです。UIKit は不要です。

| プロパティ | 型 | 意味 |
|---|---|---|
| `count` | Int | 今の人数。初期値は 0 |
| `onChange` | `((Int) -> Void)?` | 人数が変わったときに呼ぶクロージャ。初期値は `nil` |

```swift
func increment()
```
- 目的：人数を1人増やし、`onChange` で新しい人数を知らせる
- 引数・戻り値：なし

### 画面 `TallyViewController`
入口を通った人数を数える画面です。パート1では、解放されない画面をわざと作るため、`onChange` のクロージャに `[weak self]` を付けずに `self` をそのまま使います。

- プロパティ：`counter`（TallyCounter。初期値は `TallyCounter()`）
- 部品：人数のラベル、「+1」ボタン

1. **`viewDidLoad()`**：`title` を「数取り」にし、ラベルを「0人」にする
2. **`viewDidLoad()` の続き**：`counter.onChange` にクロージャを入れる。クロージャの中で、受け取った人数をラベルに「3人」の形で出す
3. **「+1」を押したとき**：`counter.increment()` を呼ぶ
4. **`deinit`**：コンソールに「TallyViewController を解放しました」と出す

### 確かめること
上から順に試します。

- [ ] 実行する → 「数取りへ」を押す → 「数取り」と「0人」が出る
- [ ] 「+1」を3回押す → 「3人」が出る
- [ ] 左上の戻るボタンで戻る → コンソールに「TallyViewController を解放しました」が出ない
- [ ] MenuViewController を表示した状態で Debug Memory Graph ボタンを押す → 左の一覧で TallyViewController を探して選び、中央の図のスクリーンショットを PR に貼る → 一覧に TallyViewController が1件ある

## パート2：解放されるように直す（30分）

### 画面 `TallyViewController`
パート1で作った `onChange` のクロージャを、TallyViewController が解放される形に直します。

1. **`viewDidLoad()` の続き**：`counter.onChange` のクロージャが、TallyViewController を弱く参照するようにする

### 確かめること
アプリを起動し直して、上から順に試します。「TallyViewController を解放しました」が出たコンソールの出力を、文字のコピーかスクリーンショットで PR に貼ります。

- [ ] 「数取りへ」 → 「+1」を2回押す → 左上の戻るボタンで戻る → コンソールに「TallyViewController を解放しました」が出る
- [ ] MenuViewController を表示した状態で Debug Memory Graph ボタンを押す → 左の一覧に TallyViewController がない

### 説明問題
`[weak self]` を付ける前は、戻るボタンで MenuViewController に戻っても TallyViewController の `deinit` が呼ばれなかったのはなぜか？ TallyViewController から順に、何が何を強く参照していたかをたどって答えます。
