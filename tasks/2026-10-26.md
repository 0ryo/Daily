## 今日の目標
- 自分で作った構造体を JSON に変換（エンコード）し、JSON から構造体に戻す（デコード）ことを、画面やファイルを使わずに Playground だけで試す。
- Swift のプロパティ名と JSON のキー名が違うときに、`CodingKeys` で対応づけられるようになる。
- 土曜に試した `do`/`catch` を、エンコードとデコードの呼び出しで使う。

## 課題の説明と要件

### 作るもの
観た映画の記録を表す構造体。画面は作らず、Playground で print して確かめる。

### 構造体（型名は自由。ここでは「映画」と呼ぶ）
| Swift のプロパティ名 | 型 | JSON のキー名 |
|---|---|---|
| `title` | String | `movie_title` |
| `minutes` | Int | `running_minutes` |
| `isFavorite` | Bool | `is_favorite` |

- 映画は、エンコードとデコードの両方ができる。
- 映画どうしを `==` で比べられる（テストケース #3 で使う）。
- Swift のプロパティ名は上の表のとおりにし、JSON のキー名との対応は `CodingKeys` で書く。

### 入力から映画を作る（定着確認の要素）
- タイトルの文字列（入力欄から来た想定）・分・お気に入りを受け取り、映画を作る仕組みを用意する（関数・イニシャライザなど、形は自由）。
- タイトルは**前後の空白・改行を除去してから**判定し、除去後に空なら映画を作らない（失敗の表し方は、nil・エラーのどちらでもよい）。
- 分は 1〜600 の範囲だけ受け付ける。範囲外なら映画を作らない。
- 作った映画の `title` には、除去後の文字列が入る。

### 使う JSON（Playground の中に文字列として置く）
- 下の JSON は、いま書いている Playground と同じファイルの中に、**String 型の文字列**として書く（辞書型には変えない。別のファイルにも置かない）。サーバーから届いた JSON の文章を、そのまま文字列で持っている想定。
- 文字列のままではデコードの入力にならないので、デコーダーが受け取る型に合わせる部分も課題に含む。
- ファイルから JSON を読み込む方法は、水曜（1028）に扱う。

テストケース #4 で使う JSON（1件）：
```json
{"movie_title": "千と千尋の神隠し", "running_minutes": 125, "is_favorite": true}
```

テストケース #5 で使う JSON（3件の配列）：
```json
[
  {"movie_title": "トイ・ストーリー", "running_minutes": 81, "is_favorite": false},
  {"movie_title": "天空の城ラピュタ", "running_minutes": 124, "is_favorite": true},
  {"movie_title": "インサイド・ヘッド", "running_minutes": 94, "is_favorite": false}
]
```

### 制約
- 強制アンラップ（`!`）、`try!`、`as!` は使わない。
- エンコードとデコードの呼び出しは `do`/`catch` で受け、失敗したらエラーを print する（今日の JSON は正しいので catch には入らない想定。壊れた JSON は明日扱う）。
- JSON のキー名の対応には `CodingKeys` を使う（キーの変換方法を一括で指定する機能は今日は使わない。`CodingKeys` の練習のため）。
