## 課題の説明と要件

### 作るもの
カフェのメニューを JSON から読み込む型。画面は作らず、Playground で print して確かめる。

### メニューの1品（型名は自由。ここでは「品目」と呼ぶ）
| Swift のプロパティ名 | 型 | JSON のキー名 |
|---|---|---|
| `name` | String | `name` |
| `price` | Int | `price` |
| `isSoldOut` | Bool | `sold_out` |

- 品目はデコードできる（エンコードは今日は不要）。

### メニュー（型名は自由。ここでは「メニュー」と呼ぶ）
- 品目の配列を持つ。配列は**メニューの外から直接書き換えられない**（読むことはできる）。
- JSON の文字列を受け取って品目の配列を読み込む仕組みを、メニューに用意する（メソッドの名前・引数・戻り値の形は自由）。
  - **成功したとき**：配列を、読み込んだ品目で置き換える。
  - **失敗したとき**：配列は**読み込む前のまま**にする。失敗の種類（下の表）と、わかる場合は原因のキー名を print する。
- 失敗の種類は、次の4つを区別する（print の文言は自由。どの種類か・どのキーかがわかればよい）。

| 失敗の種類 | 例 |
|---|---|
| JSON の形が壊れている | 閉じかっこがない、空の文字列 |
| キーがない | `price` が書かれていない |
| 型が違う | `price` が数ではなく文字列 |
| 値が null | `name` が `null` |

- 上の4つ以外の失敗が起きた場合も、クラッシュせず「その他の失敗」として print する。

### try? を使う版（1か所だけ）
- 上とは別に、JSON の文字列を受け取り、**失敗したら空の配列を返す**関数を1つ作る。この関数の中では `try?` を使う（`do`/`catch` は使わない）。

### 使う JSON（Playground の中に String 型の文字列として置く。昨日と同じ置き方）

A：正しい3件
```json
[
  {"name": "ブレンド", "price": 450, "sold_out": false},
  {"name": "カフェラテ", "price": 520, "sold_out": false},
  {"name": "チーズケーキ", "price": 480, "sold_out": true}
]
```

B：閉じかっこがない
```json
[
  {"name": "ブレンド", "price": 450, "sold_out": false}
```

C：`price` がない
```json
[{"name": "ブレンド", "sold_out": false}]
```

D：`price` が文字列
```json
[{"name": "ブレンド", "price": "450", "sold_out": false}]
```

E：`name` が null
```json
[{"name": null, "price": 450, "sold_out": false}]
```

F：空の文字列（`""`）

G：空の配列
```json
[]
```

### 制約
- 強制アンラップ（`!`）、`try!`、`as!` は使わない。
- 失敗の種類の区別は `catch` の側で行う（エラーの説明文の文字列を調べて区別しない）。
- `try?` は「try? を使う版」の1か所だけで使う。
- JSON のキー名の対応には `CodingKeys` を使う（昨日と同じく、キーの変換方法を一括で指定する機能は使わない）。
