## 課題の説明と要件

### 作るもの
読んだ本のタイトルと評価（1〜5）を記録する、1画面の読書メモアプリ。追加した本はファイルに保存され、アプリを再起動しても一覧に残る。

### 画面（XIB または Storyboard + Auto Layout）
| 部品 | 要件 |
|---|---|
| タイトルの入力欄（UITextField） | プレースホルダーあり |
| 評価の入力欄（UITextField） | 数字キーボード。1〜5 の数字1文字だけが入る（下の「評価欄の入力の制限」） |
| 追加ボタン | 押すと追加を試みる |
| 結果ラベル | 起動直後は「本のタイトルと評価を入力してください」 |
| 一覧（UITableView） | 追加した順に、1行に「タイトル（評価N）」の形で表示する（例：「星の王子さま（評価4）」） |

### モデル（型の名前と分け方は自分で決める）
- 本1冊は「タイトル（String）」と「評価（Int）」を持つ。ファイルに保存できるように Codable に準拠させる。
- 本の一覧に追加する処理は、成功したら true、失敗したら false を返す。
  - タイトルは前後の空白・改行を除いた結果が空でないこと。保存するのは除いた後のタイトル。
  - 評価は 1〜5 であること。
  - 不正なら一覧を一切変えずに false を返す。同じタイトルの本も追加できる。
- 「この文字列を評価欄に置いてよいか」の判断もモデル側に置く（ViewController は判断の結果を使うだけにする）。

### 保存用の型（Store。名前は自分で決める）
- 本の一覧を JSON にしてアプリの Documents ディレクトリのファイルに書き込む処理と、そのファイルから本の一覧を読み込む処理を持つ。
- 保存も読み込みも、失敗しうる処理として `throws` で表す。
- ViewController には、JSON への変換やファイルの場所の組み立てを書かない（Store を呼ぶだけにする）。
- ファイルへ書き込むときは、書き込みの途中で失敗しても前のファイルが壊れない方法を選ぶ（週の学習項目の「`.atomic` を指定する理由」）。

### 画面の動き
| 場面 | 要件 |
|---|---|
| 起動時 | Store から読み込んだ本を一覧に表示する。保存ファイルがない（初回起動）・読み込みに失敗した場合は、**クラッシュせず**空の一覧で始める |
| 追加に成功 | 一覧に追加して保存し、表示を更新する。両方の入力欄を空にし、キーボードを閉じ、結果ラベルを「追加しました」にする |
| 追加に失敗（入力が不正） | 結果ラベルを「タイトルと評価を確認してください」にする。入力欄の内容と一覧はそのまま |
| 保存に失敗 | クラッシュせず、結果ラベルを「保存に失敗しました」にする（今日は表示だけでよい。入力を残す処理などは来週以降に扱う） |

- 評価欄は、前後の空白を除いてから Int に変換する。変換できなければ追加の失敗として扱う。

### 評価欄の入力の制限（定着確認）
- 評価欄には、**変更後の文字列**が「空」または「1〜5 の数字1文字」になる変更だけを受け入れる。それ以外（0、6〜9、文字、2文字目）は入らない。
- 判断は UITextFieldDelegate で、文字が入る**前に**行う。

### 制約
- 強制アンラップ（`!`）と、`try!`、`as!` は使わない。
- `try?` を使う場合は、その箇所で失敗を無視してよい理由を説明できるようにする（下の完了条件）。
- UserDefaults は今日は使わない（一覧データはファイルに保存する。UserDefaults との使い分けは来週以降に扱う）。
- 編集・削除・行タップ・並び替えは今日の範囲外。
- 「保存ファイルがない」と「ファイルが壊れている」を区別した表示は 10/29 の課題で扱うので、今日は区別しなくてよい。
