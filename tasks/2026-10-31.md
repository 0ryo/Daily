# 10/31（土）筋トレの記録を、アプリを起動し直しても残す
- 作業場所：`1031/`（Xcode の iOS App プロジェクト。XIB + Auto Layout）
- 想定時間：6時間（パート1 約3.5時間、パート2 約2.5時間）
- パート1で、記録を追加して一覧に表示する画面を作ります。パート2で、記録をファイルに保存し、起動し直しても残るようにします。パート1が終わった時点で提出してよいです。パート2は、時間がなければ次の日に回してかまいません。

## 守ること（パート1・2 共通）
- `!`、`try!`、`as!`、`try?` を使わない（XIB の `@IBOutlet` の宣言の `!` は除く）。
- 入力の検証と記録の追加は WorkoutLog が、ファイルの保存と読み込みは WorkoutStorage（パート2で作る構造体）が行う。WorkoutViewController は、入力の取得、回数の Int への変換、WorkoutLog と WorkoutStorage の呼び出し、表示の更新、print だけを行う。
- WorkoutLog と WorkoutStorage の中では print しない。print は WorkoutViewController で行う。
- ブランチを切り、今日の `1031/` の変更だけで PR を作る（マージは不要）。

## パート1：記録を追加して一覧に表示する（約3.5時間）
### 構造体
**1. WorkoutRecord**（筋トレの記録1件）
- プロパティ：`name`（String、種目名）、`count`（Int、回数）
- 関数：なし
- 特記事項：エンコードとデコードができる。CodingKeys は不要。

**2. WorkoutLog**（記録の一覧を持ち、追加する前に入力を確かめる構造体）
- プロパティ：`records`（[WorkoutRecord]、記録の一覧。外から読めるが、外から直接書き換えられない）
- 関数：
  - **2-1. `init(records: [WorkoutRecord])`**
    - 目的：最初に持つ記録の一覧を決めて、WorkoutLog を作る。
    - 引数：`records`（[WorkoutRecord]、最初に持つ記録の一覧）
    - 戻り値：なし
    - 処理：
      - **2-1-1.** 引数 `records` を、プロパティ `records` に入れる。
  - **2-2. `add(name: String, count: Int) -> Bool`**
    - 目的：条件に合う記録だけを、一覧の末尾に加える。
    - 引数：`name`（String、入力された種目名）、`count`（Int、回数）
    - 戻り値：記録を加えたら `true`、加えなかったら `false`
    - 処理：
      - **2-2-1.** `add` が、`name` の前後の空白・改行を除去する。
      - **2-2-2.** 除去した後の種目名が空のとき、または `count` が 1〜999 の範囲にないとき、`add` は `records` を変えずに `false` を返す。
      - **2-2-3.** 除去した後の種目名が空でなく、`count` が 1〜999 の範囲にあるとき、`add` は除去した後の種目名と `count` で WorkoutRecord を作り、`records` の末尾に加えて `true` を返す。

### 画面
**3. WorkoutViewController**（画面は1つ）
- **3-1. 部品**：種目名の入力欄、回数の入力欄（数字キーボード）、追加ボタン、結果ラベル、UITableView を置く。
- **3-2. 起動したとき**：空の配列で WorkoutLog を作る。結果ラベルに「記録を入力してください」と表示する。
- **3-3. 追加ボタンを押したとき**
  - **3-3-1.** 回数の入力欄の文字列は、前後の空白・改行を除去してから Int に変換する。
  - **3-3-2.** どちらかの入力欄の文字列が取り出せないとき、Int への変換に失敗したとき、または WorkoutLog の `add`（2-2）が `false` を返したとき、結果ラベルを「種目名と回数を確認してください」にする。入力欄の内容と一覧は変えない。
  - **3-3-3.** `add` が `true` を返したとき、一覧の表示を更新し、両方の入力欄を空にして、キーボードを閉じる。結果ラベルを「追加しました」にする。
- **3-4. 一覧の行**：1行に1件の記録を「スクワット：20回」の形で表示する。並び順は WorkoutLog の `records` の順にする。

## パート2：記録をファイルに保存し、起動し直しても残す（約2.5時間）
### 構造体
**4. WorkoutStorage**（記録の一覧をファイルに保存し、読み込む構造体）
- プロパティ：`fileURL`（URL、保存先のファイル。Documents ディレクトリの中の `workouts.json`）
- 特記事項：`fileURL` は WorkoutStorage が自分で決める。WorkoutViewController は、何も渡さずに WorkoutStorage を作る。
- 関数：
  - **4-1. `save(_ records: [WorkoutRecord]) throws`**
    - 目的：記録の一覧をファイルに保存する。
    - 引数：`records`（[WorkoutRecord]、保存する記録の一覧）
    - 戻り値：なし
    - 処理：
      - **4-1-1.** `save` が、`records` を JSON にエンコードする。
      - **4-1-2.** `save` が、エンコードした結果を `fileURL` のファイルに書き込む。書き込み時に `.atomic` を指定する。
      - **4-1-3.** エンコードや書き込みに失敗したら、`save` はエラーを呼び出し元に投げる。
  - **4-2. `load() throws -> [WorkoutRecord]`**
    - 目的：保存されている記録の一覧を、ファイルから読み込む。
    - 引数：なし
    - 戻り値：読み込んだ記録の一覧
    - 処理：
      - **4-2-1.** `fileURL` のファイルがないとき、`load` はエラーを投げずに空の配列を返す。
      - **4-2-2.** ファイルがあるとき、`load` はファイルを読み込み、記録の配列にデコードして返す。
      - **4-2-3.** 読み込みやデコードに失敗したら、`load` は空の配列を返さずに、エラーを呼び出し元に投げる。

### 画面
**5. WorkoutViewController に加える処理**
- **5-1. 起動したとき**（パート1の 3-2 を、次の処理に置き換える）
  - **5-1-1.** WorkoutStorage の `fileURL` を print する（保存先のファイルの場所を確かめるため）。
  - **5-1-2.** WorkoutStorage の `load()`（4-2）を呼ぶ。成功したら、`load()` が返した配列で WorkoutLog を作り、一覧に表示する。結果ラベルに「記録を入力してください」と表示する。
  - **5-1-3.** `load()` がエラーを投げたら、空の配列で WorkoutLog を作る。結果ラベルを「保存データを読み込めなかったため、空の一覧で始めます」にし、エラーの内容を print する。
- **5-2. 追加した後の保存**
  - **5-2-1.** `add` が `true` を返したとき、3-3-3 の処理に続けて、WorkoutStorage の `save(_:)`（4-1）で WorkoutLog の `records` を保存する。
  - **5-2-2.** `save(_:)` がエラーを投げたら、3-3-3 で表示した「追加しました」の代わりに、結果ラベルを「追加しましたが、保存に失敗しました」にし、エラーの内容を print する。
