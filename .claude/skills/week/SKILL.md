# 週の振り返り（week）

コードは書かない。判定・記録・来週の短期目標の提案だけを行う。**plan/ のファイルは、学習者の承認なしに変更しない。** 目標の運用は `plan/goals.md` の冒頭に従う（長期・中期は goals.md、短期は1週間分だけ）。`plan/archive/`（旧計画）は読まない。

## 1. 対象の週を決める
1. `python3 .claude/scripts/teacher_context.py` を実行する。引数で週番号が渡されていればその週、なければ今日の週を対象にする（週は土曜始まり。金曜の振り返りは今週、土曜の朝に前週を振り返る場合は前週）。どの週を振り返るかを1行で伝える。
2. `plan/short-term/week-XX.md`（今週の短期目標）、`plan/goals.md`（長期目標と、今月・来月の中期目標）、その週の日付の `tasks/` と `reviews/`、`progress/log.md` を読む。今週の短期目標がない場合（運用を始めた直後など）は、3〜5 を飛ばして 6 で今週の分を作る。

## 2. 弱点を更新する
Skill ツールで `weakness` を実行し、progress/weakness.md を最新にする。

## 3. 判定する
1. 短期目標の「完了条件」を1つずつ、達成・未達成・未確認で判定する。根拠には reviews/ のファイル名や、コミット・PR を挙げる。根拠が見つからない条件は「未確認」とし、達成扱いにしない。
2. 課題の消化：短期目標の課題表の各行について、tasks/ の状態（完了・未完了・未実施）を並べる。
3. 学習時間：progress/log.md の「学習時間」をその週で合計し、基準（週25h）と比べる。
4. **UIKit と SwiftUI の進み具合**：log.md と tasks/ の「区分」ごとに、実際の学習時間を合計する。第1週からの累計の割合を、goals.md の長期目標にある配分の目安と比べる。ただし、その時期の中期目標が UIKit 中心か SwiftUI 中心かを考えて判断し、中期目標の内容から見て20%以上ずれていたら指摘する。
5. 採点の推移：その週の reviews/ の合計点と、観点ごとのレベルの平均。

## 4. 見通し
- 完了条件の未達成が2件以上、課題の未実施が2日分以上、または学習時間が基準の8割未満なら「遅れ」と判定する。遅れは責めず、来週の短期目標で吸収する。
- 今月の中期目標を月末までに終えられそうかを1〜2文で伝える。終えられそうになければ、中期目標を直す案（翌月へ移す項目など）を出し、**学習者が承認したら** goals.md を直す。App1 の App Store 公開と月1回の AIなし課題は、なるべく動かさない前提で考える。

## 5. 記録する
`progress/weekly/week-XX.md` を次の形式で作る（既にあれば末尾に「## 再判定（YYYY-MM-DD）」として追記する）。

```
# 第N週の振り返り（YYYY-MM-DD〜YYYY-MM-DD）

- 判定日: YYYY-MM-DD
- 総合: 予定どおり／遅れ（理由）

## 完了条件の達成状況
| 完了条件 | 判定 | 根拠 |
|---|---|---|

## 課題の消化
| 日 | 課題 | 状態 | 点数 |
|---|---|---|---|

## 学習時間
| 区分 | 実績 | 第1週からの累計 | 累計の割合（目安） |
|---|---|---|---|
| UIKit | | | |
| SwiftUI | | | |
| 相互運用 | | | |
| 共通 | | | |
| 合計 | | | |

## 採点の推移
## 弱点（progress/weakness.md の上位）
## 見通し（中期目標に対して）
## 来週の短期目標（plan/short-term/week-XX.md へのリンク）
```

## 6. 来週の短期目標を作る
1. 今週の判定（未達成の完了条件・未実施の課題）、progress/weakness.md、今月（月をまたぐなら来月も）の中期目標、学習者がチャットで伝えた希望（「ここをもう少し学びたい」など）から、来週の短期目標の案を作る。
   - 未達成・未実施のものは、来週の課題にするか、「来週以降の候補」に残すかを決める。
   - 1日に新しい概念を詰め込みすぎない。新しい概念を組み合わせる統合課題は、その部品を1つずつ試した日より後に置く。
   - 平日2.5h、土日6.5h に収める。金曜は過去の範囲の定着確認を1つ入れる（その週の目的に合わなければ省いてよい）。
   - その週に AIなし課題（CP）を入れるかは、checkpoints.md と中期目標を見て決める。
2. 案を、`plan/short-term/` の既存の週ファイルと同じ形（作成日・中期目標・前週からの持ち越し、今週の目標、課題表、完了条件、来週以降の候補）で**チャットに全文貼り**、学習者に確認する。
3. 学習者が承認したら `plan/short-term/week-XX.md` に保存し、goals.md の「短期目標」の「今週」のリンクを新しい週に更新する。修正の希望があれば反映してから保存する。2週間以上先の週ファイルは作らない。

最後に、記録ファイルを先生役がコミットする（1日の終わりに claude/MMDD-records ブランチで push・PR・main へのマージまで行う）。
