# 週の振り返り（week）

コードは書かない。判定・記録・提案だけを行う。**plan/ の計画ファイルは、学習者の承認なしに変更しない。**

## 1. 対象の週を決める
1. `python3 .claude/scripts/teacher_context.py` を実行する。引数で週番号が渡されていればその週、なければ今日の週を対象にする（週は土曜始まり。金曜の振り返りは今週、土曜の朝に前週を振り返る場合は前週）。どの週を振り返るかを1行で伝える。
2. `plan/weeks/week-XX.md`、`plan/roadmap.md`、その週の日付の `tasks/` と `reviews/`、`progress/log.md` を読む。

## 2. 弱点を更新する
Skill ツールで `weakness` を実行し、progress/weakness.md を最新にする。

## 3. 判定する
1. 週ファイルの「完了条件」を1つずつ、達成・未達成・未確認で判定する。根拠には reviews/ のファイル名や、コミット・PR を挙げる。根拠が見つからない条件は「未確認」とし、達成扱いにしない。
2. 課題の消化：週ファイルの課題表の各行について、tasks/ の状態（完了・未完了・未実施）を並べる。
3. 学習時間：progress/log.md の「学習時間」をその週で合計し、計画（25h、第24週は20.5h）と比べる。
4. **UIKit と SwiftUI の進み具合**：log.md と tasks/ の「区分」ごとに、実際の学習時間を合計する。週ファイルの「時間配分」の区分別の合計と比べ、さらに第1週からの累計を roadmap.md の配分表の累計と比べる。区分ごとの累計が計画から20%以上ずれていたら、ずれを指摘する。
5. 採点の推移：その週の reviews/ の合計点と、観点ごとのレベルの平均。

## 4. 見通しと修正案
- 完了条件の未達成が2件以上、課題の未実施が2日分以上、または学習時間が計画の8割未満なら「遅れ」と判定する。
- 遅れの場合は、roadmap.md の「遅れたときの調整」の順番に従って、次週以降の具体的な修正案（どの週のどの課題を削る・移す・縮める）を出す。App Store 公開（第14週）と AIなし課題は動かさない前提で考える。
- 修正案は提案にとどめ、**学習者が承認したら**該当する plan/ のファイルを編集する。
- 遅れていなくても、次週の最初の課題と、注意すべき弱点を1〜2点伝える。

## 5. 記録する
`progress/weekly/week-XX.md` を次の形式で作る（既にあれば末尾に「## 再判定（YYYY-MM-DD）」として追記する）。

```
# 第N週の振り返り（YYYY-MM-DD〜YYYY-MM-DD）

- 判定日: YYYY-MM-DD
- 総合: 予定どおり／遅れ（理由）

## 完了条件の達成状況
| 完了条件 | 判定 | 根拠 |
|---|---|---|

## 課題の消化
| 日 | 課題 | 状態 | 点数 |
|---|---|---|---|

## 学習時間
| 区分 | 計画 | 実績 | 第1週からの累計（計画／実績） |
|---|---|---|---|
| UIKit | | | |
| SwiftUI | | | |
| 相互運用 | | | |
| 共通 | | | |
| 合計 | | | |

## 採点の推移
## 弱点（progress/weakness.md の上位）
## 見通しと計画修正案
```

最後に、記録ファイルを先生役がコミットする（main にいるときは先にブランチを切る。push と PR は学習者）。
