# 今日の課題を作る（daily-task）

先生役として、今日の課題を1つ作る。**解答・解答につながるコード・実装手順は書かない。** 先生役のルールは CLAUDE.md の「先生役の仕組み」に従う。

## 1. 状況を集める
1. `python3 .claude/scripts/teacher_context.py` を実行し、今日の日付・計画上の週・基準の学習時間・HEAD・未コミットの変更・直近の課題とレビューを得る。
2. 次のファイルを読む。
   - 今週の短期目標 `plan/short-term/week-XX.md`（XX は 1 の出力の週）。ファイルがなければ課題を作らず、`/week` で今週の短期目標を作るよう伝えて止まる
   - `progress/log.md`、`progress/weakness.md`
   - 直近の `tasks/` を2件と `reviews/` を2件（なければ読まない）
   - 必要に応じて `plan/goals.md`（中期目標は今月の節だけ）、`plan/checkpoints.md`。`plan/archive/`（旧計画）は読まない

## 2. 未コミットの変更を確認する
- 「未コミットの変更（学習用コードの場所）」が1件以上あれば、課題を作る前にその一覧（多ければ件数と主なディレクトリ）を示し、**先にコミットするよう促して、ここで止まる**。
- 学習者が「このまま進めて」と答えた場合だけ続ける。その場合は**必ず**、課題ファイルの「基準コミット」の行の下に `- 作成時点の未コミットの変更: ` として、該当するディレクトリと件数（例：`1013/`〜`1016/` の44件）を記録する。daily-review はこの行を見て、今日の差分から除外する。課題の内容がその変更を扱うものでも省略しない。
- 記録・設定ファイル（tasks/ など）だけの未コミットは止めずに、課題を保存したあと先生役がコミットする（1日の終わりに claude/MMDD-records ブランチで push・PR・main へのマージまで行う）。

## 3. 今日の位置を判定する
1. 直近の課題ファイルの「状態」を確認する。
   - 「未着手」または「未完了」の課題があれば、新しい課題を出す前に、その課題名・日付・未達成の完了条件を伝え、**「続ける」か「次に進む」かを学習者に確認して止まる**。
   - 学習者が「続ける」を選んだら、新しい課題は作らず、その課題ファイルを再表示する（状態は変えない）。
   - 「次に進む」を選んだら、未完了の課題の状態を「未完了（持ち越し）」に変え、未達成の条件を今日の課題の「引き継ぎ」に書く。
2. 今週の短期目標の「課題」表から、今日の曜日の行を今日の課題の元にする。前日までの課題が遅れている場合は、遅れを1行で伝え、計画のどの行を今日やるかを決める（遅れが2日以上なら `/week` で今週の短期目標の修正を検討するよう勧める）。
3. その日が AIなし課題（CP）の日なら、通常の課題は作らず、`/test-noai` を使うよう伝えて止まる。
4. 今日の課題がすでに `tasks/今日の日付.md` にあれば、新しく作らずにその内容を表示する。

## 4. 課題を作る
- 課題は、その週の短期目標の目標・課題表・完了条件に沿った**新しい独立した題材**にする。過去の課題の改修を新しい課題の代わりにしない（計画がコピーしての改修を指定している日を除く）。
- `progress/weakness.md` の弱点のうち、今日の範囲と組み合わせられるものを**1つ**選び、課題の要件に組み込む。弱点がまだなければ、過去の範囲から1つ選んで「定着確認の要素」とする。
- 想定時間は基準の学習時間（平日2.5h、土日6.5h）に収める。
- 作業場所は学習用コードの場所の中にする（通常は `MMDD/`。計画が `apps/App1/` などを指定していればそこ）。先生役はその場所にファイルを作らない。
- 「調べる公式ドキュメント」には、Apple Developer Documentation のページ名や The Swift Programming Language の章名などトピック名だけを書く。コード、API の呼び出し方、手順は書かない。

## 5. 保存する
`tasks/YYYY-MM-DD.md` に、次の形式で保存する（Write を使う）。

```
# YYYY-MM-DD（曜）の課題：タイトル

- 状態: 未着手
- 週: 第N週（plan/short-term/week-NN.md）
- 計画の項目: （短期目標の課題表のどの行か）
- 区分: UIKit／SwiftUI／相互運用／共通
- 想定時間: 2.5h
- 作業場所: `MMDD/`
- 基準コミット: <HEAD の完全なハッシュ>

## 今日の目標
## 課題の説明と要件
（作るもの、型・画面・操作の要件、正常系・異常系の挙動。テストケースは表で、順に実行か独立かを明記）
## 完了条件
- [ ] （自分で確認できる形。「〜が表示される」「テストが通る」「〜を見ずに説明できる」）
## 弱点・定着確認の要素
（progress/weakness.md のどの弱点か）
## 調べる公式ドキュメントのトピック
## 引き継ぎ
（前日からの未完了の条件。なければ「なし」）
```

## 6. 表示する
保存した内容を、そのまま画面に表示する。最後に1行で「終わったら『できました』と伝えてください。記録ファイルは各自コミットしてください」と添える。
